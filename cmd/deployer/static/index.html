Config ownership

User-managed is the default. The operator seeds initial provider/model config, then UI, CLI, plugin, skill, MCP, and agent config edits persist on the PVC. Operator-managed keeps reconciling runtime config from this form and the Claw CR.

Give your OpenClaw starting instructions, memory, or skills. Most people skip this — you can always add files later from inside the running OpenClaw.

What can these files contain?

A directory tree that seeds the Claw's OpenClaw home (~/.openclaw, on its persistent volume). It is applied once on first boot; edits made later inside the running Claw are preserved.

  • workspace-main/ → the agent workspace (~/.openclaw/workspace/): e.g. AGENTS.md, SOUL.md, memory/, skills/
  • openclaw.json → merged into the Claw's effective config (not copied as a workspace file)
  • any other top-level folder → copied under ~/.openclaw/ (e.g. skills/ → ~/.openclaw/skills/)

For Git, the repository root is used, or the subpath you set below. Private repositories use spec.agentFiles.git.secretRef.

Full layout reference and examples: redhat-et/claw-collections.
